# DreamTune download and Android playback fixes

## What changed
- Android online playback now uses the same chunked `/api/stream` audio path as the working web player. The native ExoPlayer path is retained only for already-saved legacy phone-file URIs.
- Android downloads now use the shared chunked fetch path instead of the separate one-shot NewPipe native downloader.
- Long audio is no longer routed away solely because its duration exceeds 12 minutes; the app fetch path supports files up to the configured 220 MB safety limit.
- Download progress is shown in the Downloads view while the file is being fetched.
- The server validates upstream byte ranges and correctly slices a full-file response when an upstream server ignores Range, avoiding repeated/corrupted chunks.

## Required deployment
1. Deploy the project to Netlify so `public/music.js` and `netlify/functions/api.js` are both updated.
2. Rebuild the Android APK from the updated `android-app` source and install that APK. The Capacitor app loads `https://dreamtune7.netlify.app`, so the website/backend deployment is required even after rebuilding the APK.
3. Clear the app's website cache or reinstall if it continues to load old JavaScript.

## Verification
JavaScript syntax was checked with Node.js. Real YouTube extraction, Netlify production responses, and playback/download on a physical Android device have not been tested in this environment. The YouTube source must expose a permitted audio stream and the device must have enough storage and memory.
